PART 1. NON-NEGOTIABLE RULES (APPLY TO EVERY LINE OF CODE)
=====================================================================

R1. One ledger, one writer. Every journal entry in the system is written only by postJournal in src/lib/accounting/journalEngine.ts. No route, posting rule, or module writes JournalEntry/JournalLine/AccountBalance rows directly.
R2. Double entry always. Every posted entry has at least two lines, every line has exactly one positive side (debit > 0 and credit = 0, or credit > 0 and debit = 0), and sum(debit) equals sum(credit) to the cent in base currency. Anything else is rejected with ACCT_UNBALANCED or ACCT_LINE_INVALID.
R3. Posted entries are immutable. Corrections are reversals plus new entries. Drafts can be edited or deleted; posted, reversed, and system entries cannot be edited or deleted.
R4. Source documents stay the source of truth. Booking.amountDue, PosSale.amountDue, GiftCard.remainingBalance, PosProduct.onHand and the other existing balances stay authoritative for their modules. Accounting reads them and posts entries; it never stores a second competing balance on those documents and never recalculates tax that a source document already computed.
R5. Money math uses Prisma.Decimal (or decimal strings) only, rounded half-up to 2 decimals in base currency. Never use JS floating point for money. Float sources (Order, TaxSettings.rate) are converted once at the boundary in src/lib/accounting/money.ts. Int minor sources are divided by 100 with Decimal.
R6. Tenant isolation. orgId always comes from the actor (requireActorOrgId) or the resolved published org for public routes. Any body or query orgId is rejected with 400 ACCT_BODY_ORG_REJECTED. Cross-tenant ids return 404 ACCT_NOT_FOUND (never 403) so existence is not leaked. Every new table has orgId (required, indexed, FK Organization, onDelete Cascade). Every park-specific row has locationId (FK VenueLocation); company-level rows use locationId null.
R7. Location scope. Park-locked actors (MembershipVenueAssignment) and Enterprise HQ location preference filter every accounting list, report, and document by locationId. Park-locked actors never see company-level (locationId null) lines or company-wide balance sheet totals; they see park-level P&L, park documents, and park bank accounts only. Writes to a location must pass assertActorCanAccessLocation and reject archived venues (ACCT_LOCATION_ARCHIVED) for new documents. Money events for existing documents at an archived venue still post.
R8. Gates. Staff accounting routes call, in order: requirePermissionFresh(permission), requireActorOrgId, assertModuleEnabled(orgId, "accounting") (which runs assertOrganizationActive, assertCompanyBillingEntitled, Demo deny, storefront deny, moduleHints), soft-hold create deny on mutations, then actorLocationScope. DEFAULT_ORG / isDefault storefront never gets accounting. Demo is locked out.
R9. System posting never loses money events. Entitlement gates only staff UI and APIs. If an org has AccountingSettings.enabled = true, every money event is written to the posting outbox in the same database transaction as the source event, even if the org is soft-held, past_due, or later demoted. Ledger data is never deleted on demotion, suspension, or offboarding.
R10. A failure in accounting posting must never fail a sale, payment, refund, webhook, or booking. The outbox row is committed with the source event; the actual posting runs after commit and failed postings stay in the queue with an error for retry and review.
R11. Idempotency. Every system journal has idempotencyKey = sourceType:sourceId:sourceEvent with a unique (orgId, idempotencyKey) constraint. Webhook replays, success-URL races, offline POS re-sync, and backfill re-runs must never create duplicate entries.
R12. Periods. Entries are dated by entryDate in the org accounting timezone. Manual entries into a closed or locked period are rejected (ACCT_PERIOD_CLOSED / ACCT_PERIOD_LOCKED). System entries whose natural date falls in a closed period post on the first day of the earliest open period after it, keeping originalDate and lateForPeriodId, so history stays closed and nothing is lost.
R13. Never reopen /signup or POST /api/auth/signup. Never create client users. Customer screens stay in /profile; tailor /tailor/* gets nothing accounting-related; staff accounting lives only under /admin/accounting* and /api/admin/accounting*.
R14. Do not fake-implement QuickBooks/Xero live sync, payroll, fixed-asset depreciation schedules, or multi-entity consolidation. Only what is written here is built.
R15. Match the surrounding code style (route handler shape, response helpers in src/lib/response.ts, zod validation, error classes). Comment only constraints the code cannot show.
