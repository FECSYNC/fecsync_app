## Decisions

- Migration folder: `prisma/migrations/20261111160000_accounting_foundation`. Generated with `prisma migrate diff` and applied with `prisma db execute` + `prisma migrate resolve --applied`, because the remote database has an older unapplied migration (`20261028160000_guest_marketing_automation`) that `migrate dev` would treat as drift and offer to reset.
- `prisma generate` wrote the new typings; the engine DLL rename hit EPERM because `yarn dev` holds it (same engine version, so runtime is unaffected; restart the dev server to load the new client).
- Refund rule (S1-F1): refunds always post Dr Accounts receivable (booking customer) and Cr the tender account (gift card refunds Cr gift card liability). `refundBooking` records the reason only in BookingActivity, and a partial refund on a confirmed booking raises `Booking.amountDue` again, so there is no goodwill classification. Revenue moves only when booking status or total changes (cancelled / expired / refunded bookings reverse revenue). AR per booking therefore always equals the booking balance.
- Sync posting model: each source document (booking, POS sale, till session, membership attempt, marketplace booking, shop order, tailoring job, gift card ledger row, inventory movement) gets one outbox row per event key; re-enqueue bumps `version`. Posting rules reconcile the ledger to the document's current state using idempotent journal keys, so replays never duplicate and later changes always post their delta.
